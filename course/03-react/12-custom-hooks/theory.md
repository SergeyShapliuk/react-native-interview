# 3.12 Кастомные хуки как единица переиспользования — theory

> 🟡 DEEP DIVE. Семь углов разбора. Урок отвечает не на вопрос «как написать свой хук» — а на вопрос, **что именно переиспользует хук, и каким должен быть его контракт, чтобы вызывающий код не ломался**.

---

## 1. Что это

**Кастомный хук** — функция, имя которой начинается с `use` и которая вызывает другие хуки. Синтаксически это обычная функция; особенной её делает то, что она вызывается во время рендера компонента и её хуки записываются на fiber этого компонента.

```js
function useAppState() {
  const [state, setState] = useState(AppState.currentState);
  useEffect(() => {
    const sub = AppState.addEventListener('change', setState);
    return () => sub.remove();
  }, []);
  return state;
}
```

Хук упаковывает **логику** — состояние, эффекты, вычисления — и отдаёт наружу результат. О разметке он ничего не знает.

### Ключевая формулировка урока

> **Хук переиспользует логику, а не состояние. Два вызова одного хука — два независимых состояния.**

---

## 2. Как это работает

### Хук разворачивается в тело компонента

Для React кастомного хука не существует. Когда компонент вызывает `useAppState()`, внутри выполняются `useState` и `useEffect` — и записываются в список хуков **этого компонента** (3.5), как если бы они были написаны прямо в его теле. Хук не создаёт нового уровня, нового fiber или нового хранилища.

Три следствия:

**Состояние не разделяется.** Два компонента, вызвавших `useCart()`, получают два независимых `useState`. Добавление товара в одном не видно в другом. Хук — не способ сделать общие данные; для этого нужно поднять состояние, контекст (3.14) или внешний стор (3.19, 6.3).

**Правила хуков действуют внутри.** Тот же запрет на условный вызов, тот же список по порядку. Условный хук внутри кастомного хука сдвигает список хуков вызывающего компонента.

**Эффекты хука — эффекты компонента.** Подписка внутри `useAppState` создаётся при монтировании компонента и снимается при его размонтировании; StrictMode проверяет её так же (3.4).

### Префикс `use` — не косметика

Имя с `use` делает три вещи:

- **включает проверки линтера** — `rules-of-hooks` проверяет, что хук вызывается на верхнем уровне компонента или другого хука, а внутри хука — что его собственные хуки вызываются по правилам;
- **сообщает React Compiler**, что функция — хук, и к ней применимы правила хуков (3.18);
- **сообщает читателю**: этот вызов нельзя поставить под условие и нельзя вызвать в обработчике.

Функция с хуками, но без префикса (`getTheme()` с `useContext` внутри) обходит все три проверки. Обратное — префикс `use` у функции без хуков — ограничивает места вызова без причины.

### Когда хук не нужен

Если логика не использует ни состояния, ни эффектов, ни других хуков — это обычная функция:

```js
function formatDuration(sec) { /* ... */ }          // правильно
function useFormatDuration(sec) { /* ... */ }       // лишнее ограничение
```

`useFormatDuration` нельзя вызвать в обработчике, в цикле, в другом модуле вне компонента, в тесте без рендера. Ничего не выиграно.

### Контракт возвращаемого значения

Возврат хука — публичный API, который используют десятки вызовов. Три решения в нём:

**Форма.** Кортеж — когда значений два и имена очевидны по позиции, а вызывающий может захотеть назвать их сам (`const [query, setQuery] = useSearch()`; два экземпляра хука на экране). Объект — когда значений больше двух, они необязательны или набор будет расти. Типизация обеих форм — 2.14.

**Стабильность функций.** Функция, возвращённая хуком, попадёт в пропсы `memo`-компонентов и в зависимости эффектов вызывающего. Если она новая на каждый рендер, у вызывающего ломается мемоизация и перезапускаются эффекты — и причина не видна в его коде. Поэтому стабильность возвращаемых функций — **часть контракта**, а не деталь реализации:

```js
function useLessonProgress(lessonId) {
  const [percent, setPercent] = useState(0);
  const save = useCallback(() => api.saveProgress(lessonId, percent), [lessonId, percent]);
  // save меняется при каждом изменении percent — это нужно знать вызывающему
  return { percent, setPercent, save };
}
```

Если стабильность невозможна или не нужна, контракт это говорит явно (комментарием, типом, именем). Хуже всего — функция, которая «обычно» стабильна.

**Стабильность объекта.** Объект `{ percent, save }`, возвращённый литералом, — новый на каждый рендер. Пока вызывающий деструктурирует его, это безвредно. Если хук подразумевает, что объект передают целиком в `memo`-компонент или в зависимости, — объект оборачивается в `useMemo`.

### Хук-обёртка над внешней системой

Самая ценная разновидность хука: императивный источник событий превращается в значение. Эффект с очисткой спрятан внутри, наружу — данные:

```js
function useKeyboardHeight() {
  const [height, setHeight] = useState(0);
  useEffect(() => {
    const show = Keyboard.addListener('keyboardDidShow', (e) => setHeight(e.endCoordinates.height));
    const hide = Keyboard.addListener('keyboardDidHide', () => setHeight(0));
    return () => { show.remove(); hide.remove(); };
  }, []);
  return height;
}
```

Это ровно шаблон 8 из 3.7 — синхронизация с внешней системой, — упакованный так, что вызывающий не может забыть очистку. Для источников, которые меняются во время рендера или читаются многими компонентами, правильнее `useSyncExternalStore` (3.19).

### Хук, принимающий зависимости

```js
const state = useAsync(() => api.loadLesson(lessonId, lang), [lessonId, lang]);
```

Хук передаёт массив вызывающего во внутренний `useEffect`. Внутри хука линтер не может проверить такой массив и требует подавления с комментарием — это одно из немногих честных исключений из правила 3.5. Проверку переносят на место вызова: опция `additionalHooks` правила `exhaustive-deps` (`additionalHooks: '^useAsync$'`) заставляет линтер проверять зависимости у каждого вызова `useAsync` так же, как у `useEffect`. Проверено: пропущенный `lang` на месте вызова даёт предупреждение «React Hook useAsync has a missing dependency: 'lang'».

## 3. Почему это важно

**Хук — основная единица переиспользования логики в современном React.** Миксины, HOC и render props решали эту задачу раньше и хуже (3.13). Почти вся инфраструктура проекта — подписки на платформу, работа с формами, загрузка данных, обёртки над нативными модулями — живёт в хуках. Качество их контрактов определяет качество всего кода, который их вызывает.

**Ошибка в хуке тиражируется.** Нестабильная функция в возврате ломает мемоизацию в каждом вызывающем компоненте; пропущенная очистка даёт утечку на каждом экране, где хук вызван; хук, используемый как общий стор, создаёт рассинхронизированные копии по всему приложению.

**Хук скрывает эффекты.** `const height = useKeyboardHeight()` выглядит как чтение значения, а на деле — подписка на нативные события с ре-рендером компонента при каждом показе клавиатуры. Это удобство, но и ответственность: контракт хука должен говорить, что он делает с жизненным циклом вызывающего.

---

## 4. Где это в React Native

Типовой набор, который в RN-проекте возникает сам:

- **`useAppState`** — приложение активно, в фоне или неактивно; для паузы видео, обновления данных при возврате, остановки опроса;
- **`useKeyboardHeight`** / `useKeyboardVisible` — отступ под клавиатуру там, где `KeyboardAvoidingView` не подходит;
- **`useDebouncedValue`** / **`useDebouncedCallback`** — поиск по мере ввода без запроса на каждый символ;
- **`useThrottledCallback`** — обработчик прокрутки или жеста, вызываемый не чаще раза в N мс;
- **обёртка над нативным модулем** — emitter загрузки, геолокации, Bluetooth, превращённый в значение;
- **`useAsync`** — загрузка данных с состоянием `idle / pending / success / error`, базовая версия; полноценная — с кэшем, гонками и отменой — TanStack Query или RTK Query (блок 07).

Некоторые из них уже есть в RN или библиотеках: `useWindowDimensions` и `useColorScheme` — хуки-обёртки над внешними системами из ядра RN. Свой хук стоит писать, когда готового нет или его контракт не подходит.

### Хуки и навигация

Хук с подпиской, вызванный в экране стека, живёт столько же, сколько экран, — то есть и тогда, когда экран под другим (3.4). `useAppState` в невидимом экране продолжает реагировать на смену состояния приложения. Если хук должен работать только для видимого экрана, он опирается на события фокуса навигации (4.17).

## 5. Типичные ошибки

**Хук как способ разделить состояние.** `useCart()` в шапке и в списке товаров, ожидание, что они видят одну корзину. Возникает из аналогии «хук — это сервис». Каждый вызов — своё состояние. Общие данные — поднятое состояние, контекст или стор.

**Хук-«мешок» на весь экран.** `useLessonScreen()` возвращает двадцать значений и функций. Возникает при выносе логики «чтобы компонент был короче». Хук не переиспользуется (он нужен одному экрану), но прячет связи между частями логики и возвращает объект, любое изменение которого затрагивает всё. Хуки выделяют по смыслу — один хук, одна ответственность.

**Нестабильные функции в возврате.** Возникает, когда хук пишут для одного вызывающего, у которого нет `memo`. Второй вызывающий передаёт функцию в `memo`-компонент или в эффект — и получает перезапуски на каждый рендер, причину которых не видно в его коде.

**Хук без префикса `use`.** Возникает при выносе кода из компонента «в утилиту». Линтер и компилятор перестают проверять правила хуков в этой функции и в местах её вызова.

**Префикс `use` у функции без хуков.** Возникает из правила «всё, что относится к React, — хук». Функция теряет возможность вызываться в обработчиках и тестах без рендера.

**Подавление `exhaustive-deps` внутри хука без переноса проверки.** Хук принимает `deps`, внутри стоит `eslint-disable`, а на месте вызова никто не проверяет массив. Решение — `additionalHooks`.

## 6. Trade-offs

### Хук скрывает эффекты

Хук делает вызывающий код коротким и декларативным, а цена — скрытые подписки, таймеры и ре-рендеры. Компонент, вызывающий пять хуков, может иметь пять подписок на нативные события, и это видно, только если открыть каждый хук. Компенсация — имена, говорящие о поведении (`useKeyboardHeight` очевидно подписывается на клавиатуру), и описание контракта: что хук подписывает, когда вызывает ре-рендер, что стабильно.

### Общий хук против специализированного

`useAsync(fn, deps)` универсален и подходит любому экрану, но каждый вызывающий сам решает про ключи, отмену и кэш. `useLesson(lessonId)` поверх `useAsync` специализирован: знает, как загружать урок, какие ошибки ожидать, — и не переиспользуется для курсов. Универсальный хук — инфраструктура, специализированный — часть домена. Проект обычно нуждается в обоих слоях.

### Свой хук против библиотеки

Свой `useDebounce` — 15 строк, понятных команде. Свой `useAsync` с кэшем, повторами, отменой и инвалидацией — это уже собственная версия TanStack Query, с собственными ошибками. Граница — там, где логика перестаёт быть механизмом React и становится доменом другой задачи (кэширование серверных данных — блок 07).
