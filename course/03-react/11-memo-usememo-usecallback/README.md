## Что внутри

`memo`: пропуск рендера при поверхностно равных пропсах; кастомный компаратор и его опасность · `useMemo`: кэш одного значения — для дорогого вычисления и для стабильной ссылки, которую кто-то сравнивает · `useCallback` как `useMemo` для функции · цепочка: `useCallback` без `memo` у получателя ничего не даёт; `memo` без стабильных пропсов ничего не даёт; `children` ломает `memo` · стоимость мемоизации · альтернативы до мемоизации: опустить состояние вниз, поднять содержимое вверх · мемоизация — подсказка, а не гарантия · где в RN: ячейка списка — место, где мемоизация окупается почти всегда · ошибки: `useCallback` на всё, `useMemo` для дешёвого `filter`, `memo` на компоненте с `children`.

## Ключевая формулировка урока

**Мемоизация — это не оптимизация сама по себе, а обещание стабильной ссылки. Она окупается, только если кто-то эту стабильность проверяет: `memo`-компонент, зависимость эффекта или дорогое вычисление.**
