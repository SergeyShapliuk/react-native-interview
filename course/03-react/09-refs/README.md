## Цель

Решать, когда значение должно быть ref, а когда состоянием, и объяснять, почему запись в `ref.current` не вызывает рендер.

## Что внутри

Ref как ячейка на fiber, о которой React ничего не знает · почему изменение `ref.current` не ставит обновление в очередь · два законных применения: значение, не влияющее на разметку, и доступ к узлу · не читать и не писать ref при рендере (кроме ленивой инициализации) · когда заполняется ref на host-узел · ref как обычный пропс в React 19 (RN 0.78+) и `forwardRef` в старом коде · ref-колбэк и его очистка · `useImperativeHandle` как узкий контракт · где в RN: `measure`, DOM-подобные методы с 0.82, `scrollToIndex`, `focus`, animated ref, императивные методы нативных компонентов · ошибки: ref вместо состояния, `ref.current` в зависимостях · trade-offs: актуальное значение против согласованного снимка; handle как API, который придётся поддерживать.

## Ключевая формулировка урока

**Ref — это ячейка, живущая между рендерами, о которой React ничего не знает. Изменение ячейки не ставит обновление в очередь, поэтому то, что влияет на экран, в ref не хранится.**

## Границы урока

Ref разбирается вскоре после `useLayoutEffect` не случайно: это два инструмента одной ситуации — когда декларативной модели недостаточно и нужно обратиться к узлу напрямую.
