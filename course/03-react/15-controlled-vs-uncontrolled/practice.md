# 3.15 Controlled vs uncontrolled — practice

## Проверка понимания

Вопросы уровня собеседования. Правильный ответ требует назвать, **где живёт значение** и **что рендерится на символ**.

---

**1. Форма из 20 полей хранит всё в одном `useState` в корне экрана. Сколько компонентов рендерится на один символ, и как это сократить, не отказываясь от controlled-полей?**

<details>
<summary>Ответ</summary>

Рендерится компонент экрана (у него изменилось состояние) и всё его поддерево: двадцать полей, подписи, превью, кнопки — всё, что не защищено `memo` со стабильными пропсами (3.10). Обычно обработчики — стрелки вида `(t) => setForm({ ...form, title: t })`, новые на каждый рендер, поэтому `memo` на полях не сработал бы даже при наличии.

Сократить, оставив поля контролируемыми:

- **опустить состояние** — каждое поле (или секция) хранит своё значение; наверх уходит итог по `onBlur`, по отправке или с debounce. На символ рендерится одно поле;
- **`memo` на строках со стабильным обработчиком** — `const updateField = useCallback((name, value) => setForm((f) => ({ ...f, [name]: value })), [])`, строка получает `name` и `onChange={updateField}`. На символ рендерится экран и одна строка (у остальных пропсы те же);
- **разделить форму** — шаги или секции со своим состоянием.

Первый вариант дешевле всего по рендерам, второй сохраняет «одно место с данными» без цены за всю форму.

**Ответ «надо перейти на uncontrolled»** — возможно, для части полей, но вопрос был о том, как оставить controlled: цена определяется местом состояния, а не режимом.
</details>

---

**2. Почему маску телефона плохо реализовать на uncontrolled-поле, и чем платит controlled-реализация в RN?**

<details>
<summary>Ответ</summary>

Маска — это преобразование значения на каждый символ: `9161234567` → `+7 (916) 123-45-67`. Uncontrolled-поле не даёт React способа изменить показываемый текст в ответ на ввод: значение принадлежит нативному полю, `defaultValue` — только начальное. Остаётся `setNativeProps` или `clear()` + повторная вставка — обход модели, который расходится с тем, что знает React.

Controlled-реализация — `value={format(raw)}`, `onChangeText={(t) => setRaw(digits(t))}` — работает, но в RN имеет видимую цену. Символ появляется в нативном поле сразу, затем JS присылает отформатированное значение, и поле заменяет текст. Между этими моментами — круг «событие → рендер → команда полю». В `TextInput` RN 0.87 команда снабжена счётчиком событий, чтобы устаревшие подтверждения отбрасывались; но окно, в котором пользователь видит неотформатированный текст, остаётся, и курсор может прыгать при замене.

Снижение цены: маска в маленьком компоненте, чтобы рендер был минимальным; управление выделением (`selection`) после форматирования; для сложных масок — специализированные поля, выполняющие преобразование ближе к нативной стороне.

**Ответ «controlled-поле всегда мгновенное, это же React»** вскрывает незнание того, что поле нативное, а значение — подтверждение из JS.
</details>

**3. Как сбросить неконтролируемую форму заметки при переходе к следующему уроку?**

<details>
<summary>Ответ</summary>

Ключом: `<NoteEditor key={lesson.id} note={noteFor(lesson)} />`. Новый ключ — новый экземпляр: новое нативное поле с новым `defaultValue`, новый ref со значением, без следов прошлого черновика (3.2).

Если нужно очистить поле без пересоздания (например, после отправки сообщения в чате) — `inputRef.current.clear()` плюс сброс значения в ref.

Что не работает: изменить `defaultValue` и ждать, что поле обновится. `defaultValue` — начальное значение; документированного поведения «обновить поле при изменении `defaultValue`» нет, и на него нельзя опираться.

**Ответ «эффектом при смене урока очистить состояние»** — у неконтролируемого поля нет состояния React, которое можно очистить; а для controlled-формы эффект хуже ключа (3.7).
</details>

---

**4. Поле `value={props.title}` без `onChangeText`. Что видит пользователь при вводе?**

<details>
<summary>Ответ</summary>

Символ появляется — нативное поле показывает ввод сразу. Затем поле возвращается к `props.title`: `TextInput` видит, что значение из JS не совпадает с последним нативным текстом, и командой возвращает нативному полю значение пропса. Символ «исчезает».

Это ожидаемое поведение controlled-поля: источник истины — React, и React сказал, что значение — `props.title`. Либо поле должно быть подключено (`onChangeText` записывает в состояние, из которого берётся `value`), либо оно должно быть неконтролируемым (`defaultValue`), либо нередактируемым (`editable={false}`), если ввод не предполагается.

**Ответ «поле не даст ввести символ»** вскрывает веб-модель, где контролируемый `input` не меняется вовсе. В RN нативное поле успевает показать символ.
</details>

## Задание — форма заметки в двух режимах

**Дано.** Экран урока RN Academy, внизу — блок заметки:

- строка поиска по заметкам (результаты под полем по мере ввода);
- заголовок заметки, не длиннее 60 символов, со счётчиком «12/60»;
- текст заметки — многострочный, может быть длинным, сохраняется кнопкой;
- при переходе к другому уроку блок показывает заметку этого урока.

Текущая реализация хранит всё в состоянии экрана урока:

```jsx
function LessonScreen({ lesson }) {
  const [search, setSearch] = useState('');
  const [title, setTitle] = useState(lesson.note?.title ?? '');
  const [body, setBody] = useState(lesson.note?.body ?? '');
  // ... плеер, список разделов, всё остальное ...
  return (
    <>
      <Player uri={lesson.videoUri} />
      <Sections lesson={lesson} />
      <TextInput value={search} onChangeText={setSearch} />
      <NoteSearchResults query={search} />
      <TextInput value={title} onChangeText={(t) => setTitle(t.slice(0, 60))} />
      <Text>{title.length}/60</Text>
      <TextInput multiline value={body} onChangeText={setBody} />
      <Button title="Сохранить" onPress={() => api.saveNote(lesson.id, { title, body })} />
    </>
  );
}
```

**Требуется.**

1. Посчитать, что рендерится на один символ в каждом из трёх полей.
2. Выбрать режим для каждого поля и обосновать по требованиям.
3. Переписать блок заметки. Учесть смену урока.
4. Объяснить, почему обрезка до 60 символов в `onChangeText` хуже, чем `maxLength`, и когда без неё не обойтись.

---

<details>
<summary>Разбор</summary>

**1. Что рендерится сейчас.**

Любой символ в любом поле — обновление состояния `LessonScreen`: рендер экрана урока, плеера (если не `memo`), списка разделов, результатов поиска и всех полей. Для текста заметки это ещё и передача всего длинного текста из JS в нативное поле на каждый символ.

Отдельно: при переходе к другому уроку `title` и `body` не сбрасываются — `useState` инициализирован один раз, и экран показывает заметку прошлого урока (если экран не перемонтируется).

**2. Режимы.**

- **Поиск** — controlled: значение нужно для фильтрации на каждый символ. Но тяжёлая работа — по отложенному значению.
- **Заголовок** — controlled: счётчик «12/60» зависит от значения на каждый символ. Ограничение длины — `maxLength`.
- **Текст заметки** — uncontrolled: UI не реагирует на ввод, значение нужно только при сохранении.

**3. Переписанный блок.**

```jsx
function LessonScreen({ lesson }) {
  return (
    <>
      <Player uri={lesson.videoUri} />
      <Sections lesson={lesson} />
      <NoteSearch />
      <NoteEditor key={lesson.id} lessonId={lesson.id} note={lesson.note} />
    </>
  );
}

function NoteSearch() {
  const [search, setSearch] = useState('');
  const query = useDebouncedValue(search, 250);
  return (
    <>
      <TextInput value={search} onChangeText={setSearch} />
      <NoteSearchResults query={query} />
    </>
  );
}

function NoteEditor({ lessonId, note }) {
  const [title, setTitle] = useState(note?.title ?? '');
  const bodyRef = useRef(note?.body ?? '');
  return (
    <>
      <TextInput value={title} onChangeText={setTitle} maxLength={60} />
      <Text>{title.length}/60</Text>
      <TextInput
        multiline
        defaultValue={note?.body ?? ''}
        onChangeText={(t) => { bodyRef.current = t; }}
      />
      <Button title="Сохранить" onPress={() => api.saveNote(lessonId, { title, body: bodyRef.current })} />
    </>
  );
}
```

Что изменилось:

- **поиск** — символ рендерит только `NoteSearch`; результаты пересчитываются по `query` раз в 250 мс простоя (3.12);
- **заголовок** — символ рендерит только `NoteEditor` (несколько элементов);
- **текст заметки** — ни одного рендера на ввод; текст не гоняется через JS обратно в поле;
- **смена урока** — `key={lesson.id}` создаёт новый `NoteEditor`: новое состояние заголовка, новый ref, новое нативное поле с `defaultValue` нового урока (3.2). Без ключа неконтролируемое поле осталось бы с текстом прошлого урока.

Экран урока больше не рендерится от ввода вовсе: плеер и разделы не затрагиваются, и для этого не понадобилось ни одного `memo`.

**4. Обрезка в `onChangeText` против `maxLength`.**

`setTitle(t.slice(0, 60))` — это изменение значения в JS: пользователь вводит 61-й символ, нативное поле его показывает, затем JS возвращает обрезанное значение, и символ исчезает. На загруженном потоке — мерцание и прыжок курсора, особенно при вставке длинного текста.

`maxLength` применяется нативным полем: 61-й символ не появляется вовсе, круга через JS нет.

Обрезка в JS нужна, когда правило сложнее длины: «не больше 60 символов без учёта пробелов», запрет определённых символов, ограничение по графемам, а не по единицам UTF-16. Учтите, что `maxLength` считает длину не так, как видит её пользователь: эмодзи могут занимать несколько единиц (1.25), и поведение на платформах стоит проверять на устройстве.

**Вклад в проект (P3).** В RN Academy форма заметки разделена по режимам: поиск controlled с отложенным значением, заголовок controlled с `maxLength`, текст заметки uncontrolled со значением в ref; блок заметки сбрасывается ключом урока. Экран урока не рендерится от ввода.
</details>
