## Цель

Понимать, что React Compiler убирает из кода, на каких допущениях он работает и где ручная мемоизация и ручной контроль всё ещё нужны.

## Что внутри

Что делает компилятор: анализ компонента и мемоизация выражений, колбэков и JSX через кэш на fiber · как выглядит скомпилированный код · чего он не делает: не оборачивает компоненты в `memo`, не ускоряет рендер и commit · допущения: чистый рендер, иммутабельность, правила хуков · что происходит при нарушении: функция молча остаётся нескомпилированной · `eslint-plugin-react-hooks` 7 как линтер компилятора · `"use no memo"` · где ручная работа остаётся · где в RN: Babel-плагин, Expo SDK 54 включает его в новых проектах, шаблон RN 0.87 — нет · ячейки списка с компилятором · trade-offs: меньше ручной мемоизации против менее наглядного поведения.

## Ключевая формулировка урока

**Компилятор не делает рендер быстрее — он автоматически делает то, что делали `useMemo` и `useCallback`, и только для кода, который соблюдает правила React. Код, который их нарушает, компилятор пропускает молча.**
