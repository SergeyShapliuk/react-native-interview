## Цель блока

Понять, что React делает между вызовом `setState` и появлением пикселя, и научиться на это влиять осознанно — вместо расстановки `memo` по интуиции.

## Что должно быть получено

- Называю причину лишнего рендера по коду, не запуская профайлер.
- Решаю, где мемоизация нужна, а где вредна, и обосновываю оба случая.
- Объясняю, что сломается без стабильного `key` — вплоть до «значение в `TextInput` прыгнуло на другой элемент».
- Понимаю, какие ошибки Error Boundary не увидит, и что с ними делать.

## Checkpoint

Дан компонент на ~150 строк: инлайн-объекты в пропсах, контекст с широким `value`, список с `index` в качестве ключа, несколько эффектов с неполными зависимостями. Перечислить **все** причины лишних рендеров и доказать каждую рассуждением по коду. Затем предложить изменения, отсортированные по «выигрыш / риск», и отдельно отметить те места, где `React.memo` не поможет.

## Упражнения

- **Debugging exercise:** компонент с лишними ре-рендерами — найти причины без профайлера. К этому же компоненту возврат в блоке 05, уже с профайлером.
- **Code review exercise:** PR, где мемоизация расставлена «на всякий случай» — объяснить, что из этого бесполезно и почему.
- **Exercise:** кастомный хук `useDebounce` / `useThrottle` (из банка вопросов).
- **Exercise:** `useAsync` / `useFetch` с loading / error / data — базовая версия; полноценная работа с гонками и отменой переносится в блок 07.
