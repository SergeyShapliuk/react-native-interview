## Цель

Смотреть на эффект и отвечать, синхронизирует ли он React с чем-то внешним; если нет — удалять его, не заменяя ничем или заменяя вычислением при рендере, ключом или обработчиком.

## Что внутри

Один вопрос вместо API: синхронизирует ли эффект React с системой, которая о нём не знает · восемь шаблонов: производное значение, сброс через `key`, корректировка части состояния при рендере, обработка события в обработчике, цепочки эффектов, «пропс в стейт», уведомление родителя, синхронизация с внешней системой · что каждый лишний эффект стоит: лишний рендер и кадр рассогласования · `set-state-in-effect` в `eslint-plugin-react-hooks` 7 · где в RN граница проходит отчётливо: `AppState`, `Keyboard`, emitter'ы — да; фильтрация, суммы, `route.params` в стейт — нет.

## Ключевая формулировка урока

**Эффект — это синхронизация React с системой, которая ничего не знает о React. Всё остальное — вычисление при рендере, обработка события или новый экземпляр компонента.**

## Границы урока

Самый ценный урок блока для разработчика, который пишет на React каждый день: типовой экран содержит несколько эффектов, и значительная их часть удаляется без замены.

> **Не дублировать:** мемоизация производного значения, когда вычисление действительно дорогое, — 3.11; запросы данных, гонки и отмена — блок 07; утечки от неснятых подписок — 5.8; что вообще считать состоянием — 6.1.
