## Цель

Объяснять, почему любое изменение `value` рендерит всех подписчиков, и дробить контекст под частоту изменений.

## Материалы урока

- [practice.md](./practice.md) — проверка понимания и задание

## Что внутри

Как провайдер сравнивает `value` и помечает потребителей · подписка на весь `value`, а не на поле · `memo` защищает промежуточные компоненты, но не потребителя · `value`-литерал — новый на каждый рендер провайдера · четыре способа дробления: значения и действия раздельно, по частоте изменений, провайдер ниже, мемоизированный `value` · `use(Context)` в React 19 · когда Context — правильный выбор · где в RN: тема, локаль, safe area (insets и frame — разные контексты), сессия; плохие кандидаты — позиция скролла, прогресс воспроизведения, ввод · ошибки: Context как стор, один `AppContext` на всё.

## Ключевая формулировка урока

**Context — механизм доставки, а не управления состоянием. Подписчик рендерится при любом изменении `value` по `Object.is`, и `memo` между провайдером и подписчиком этого не останавливает.**
