## Что внутри

Update queue на fiber и почему переменная состояния не меняется после `setState` · функциональное обновление и порядок применения очереди · batching: что попадает в один рендер в React 18+ и где граница (`await`) · `flushSync` и почему в RN его нет в публичном API · scheduling: lanes и приоритет события · render phase: чистая и (иногда) прерываемая · commit phase: мутации, layout-эффекты, пассивные эффекты · bailout при том же значении и почему компонент всё же может быть вызван ещё раз · где в RN: render на JS-потоке, commit в Fabric, автоматический батчинг как свойство New Architecture · «лишний рендер» и «долгий commit» как разные проблемы.

## Ключевая формулировка урока

**`setState` не меняет состояние — он ставит обновление в очередь и просит React запланировать работу. Новое значение появится только в следующем вызове компонента.**
