## Цель

Объяснять, что такое tearing и почему подписка на внешний стор требует отдельного API, а не `useEffect` + `setState`.

## Что внутри

Внешний стор: состояние, о котором React не знает · tearing — один закоммиченный экран с данными из двух версий стора, и почему он возможен в однопоточном JS · два дефекта подписки через `useEffect` + `setState`: изменение между рендером и подпиской и tearing при прерываемом рендере · контракт `subscribe` / `getSnapshot` и какую гарантию даёт хук · почему `getSnapshot` с новым объектом зацикливает рендер · селектор поверх снимка · `getServerSnapshot` и почему в RN он почти не встречается · обновление из внешнего стора не может быть переходом · почему Zustand и React Redux перешли на этот API · где в RN: нативные модули с состоянием, MMKV, собственные сторы, хук-обёртка над нативным emitter.

## Ключевая формулировка урока

**Прерываемый рендер может прочитать внешний источник дважды — до и после его изменения. `useSyncExternalStore` гарантирует, что один рендер видит одну версию, и платит за это синхронностью.**
