## Цель

Знать, где и каким алгоритмом React сравнивает значения, и называть причину лишнего рендера по коду, без профайлера.

## Что внутри

Четыре места, где React сравнивает: `setState`, массив зависимостей, `memo`, `value` контекста · `Object.is` и shallow compare: что именно проверяется · три причины рендера компонента и почему чаще всего это рендер родителя · рендер родителя рендерит всех детей, пока на пути нет `memo` · что создаёт новую ссылку на каждый рендер · мутация и «`setState` не сработал» — и почему иногда «сработал наполовину» · где в RN: `style`, `contentContainerStyle`, `renderItem`, `data` у `FlatList`, который внутри `PureComponent` · ошибки: «компонент рендерится, только если изменились пропсы», глубокое сравнение как решение · trade-offs: дешёвое ссылочное сравнение требует иммутабельности.

## Ключевая формулировка урока

**React нигде не сравнивает содержимое. Он сравнивает ссылки — через `Object.is` для состояния, зависимостей и контекста и поверхностно, по ключам, для пропсов `memo`.**
