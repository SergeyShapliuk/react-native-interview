# 3.16 Error Boundaries — practice

## Проверка понимания

Вопросы уровня собеседования. Правильный ответ требует назвать, **кто вызывает код, в котором брошена ошибка**, — React или рантайм.

---

**1. Какие из пяти ошибок поймает ближайшая граница?**

```jsx
function LessonCard({ lesson }) {
  const title = lesson.meta.title;                         // A: lesson.meta === undefined
  useEffect(() => {
    analytics.track(lesson.id.toUpperCase());              // B: lesson.id === undefined
    const id = setTimeout(() => { JSON.parse('{'); }, 0);  // C
    return () => clearTimeout(id);
  }, [lesson]);
  async function onShare() {
    await share(lesson.url);                               // D: share отклонён
  }
  return <Pressable onPress={() => { throw new Error('E'); }} onLongPress={onShare} />;
}
```

<details>
<summary>Ответ</summary>

- **A — поймает.** Ошибка в рендере: функцию компонента вызывает React.
- **B — поймает.** Синхронное тело эффекта выполняет React в commit. Проверено на React 19.2.
- **C — не поймает.** Колбэк таймера вызывает рантайм позже, когда эффект давно закончился. Эффект только запустил эту работу.
- **D — не поймает.** Продолжение после `await` в обработчике — асинхронный код, вызванный рантаймом; отклонённый промис станет unhandled rejection (1.11).
- **E — не поймает.** Обработчик нажатия вызывает система событий в ответ на действие пользователя, а не рендер. Проверено: ошибка в обработчике не переводит границу в fallback.

Общий признак — тот же, что у `try/catch` (1.11): граница видит ошибки только внутри вызова, который React сделал сам.

**Ответ «поймает все пять, они же в компоненте»** вскрывает модель «граница ловит всё, что написано внутри компонента».

**Ответ «B не поймает, эффекты асинхронные»** вскрывает устаревшее знание: синхронное тело эффекта и его очистка ловятся.
</details>

---

**2. Как довести ошибку загрузки урока до ближайшей границы, и всегда ли это нужно?**

<details>
<summary>Ответ</summary>

Ошибка загрузки возникает в асинхронном продолжении — граница её не видит. Чтобы она попала в границу, её нужно превратить в ошибку рендера:

```jsx
const [, setState] = useState();
useEffect(() => {
  api.loadLesson(lessonId).catch((error) => setState(() => { throw error; }));
}, [lessonId]);
```

Функция-обновление вызывается при рендере (3.3), и брошенная в ней ошибка — ошибка рендера. Проверено: граница показывает fallback. Альтернатива — хранить ошибку в состоянии и бросать её при рендере (`if (state.status === 'error') throw state.error`). `useErrorBoundary` из `react-error-boundary` делает то же.

Нужно не всегда. Доводить до границы стоит ошибки, после которых **экран бессмыслен**: урок не загрузился — показывать нечего, fallback с повтором уместен. Ошибка сохранения заметки, ошибка загрузки рекомендаций, ошибка отметки «пройдено» — экран остаётся полезным, правильнее тост, повтор или деградация внутри компонента (7.3).

**Ответ «обернуть `await` в `try/catch` внутри границы»** — `try/catch` поймает ошибку, но граница об этом не узнает: её нужно ещё и передать в рендер.
</details>

---

**3. Что получит пользователь release-сборки RN 0.87, если ошибка рендера не поймана ни одной границей? А если поймана границей экрана?**

<details>
<summary>Ответ</summary>

**Не поймана.** React очищает весь корень (проверено в react-dom: корень без границы после ошибки пуст). Рендерер RN 0.87 подключает к корню обработчик `onUncaughtError`, который передаёт ошибку в `ExceptionsManager` с пометкой **фатальная**. В release фатальная JS-ошибка по умолчанию приводит к закрытию приложения — это JS-краш в отчётах (10.7). В dev — красный экран LogBox.

**Поймана границей экрана.** Граница показывает fallback вместо содержимого экрана; навигация, таб-бар, другие экраны работают. Рендерер передаёт ошибку через `onCaughtError` как **нефатальную** — она видна в LogBox в dev и может уйти в crash reporting через `componentDidCatch`, но приложение не закрывается.

Разница между закрытым приложением и одним экраном с кнопкой «Повторить» определяется тем, есть ли граница. В dev она плохо видна: и та, и другая ошибка выглядят как LogBox.

**Ответ «пользователь увидит белый экран»** — так было бы, если бы никто не обрабатывал фатальные ошибки; в RN 0.87 непойманная ошибка рендера фатальна.
</details>

---

**4. Граница стоит над стековым навигатором. Ошибка на экране урока. Что не так с этой расстановкой?**

<details>
<summary>Ответ</summary>

Fallback заменит всё поддерево границы — то есть навигатор целиком, включая шапку с кнопкой «назад» и экраны в стеке под текущим. Пользователь не может уйти с экрана, который сломался: из fallback нет навигации, кроме той, что в него явно встроена. Если повтор снова падает, выход — закрыть приложение.

Правильнее — граница **внутри** каждого экрана (или вокруг содержимого экрана): ошибка заменяет содержимое, шапка и навигация остаются, пользователь может вернуться назад. Граница на корне остаётся последним рубежом для ошибок вне экранов.

Сброс экранной границы — по ключу или `resetKeys` при смене параметров экрана: переход к другому уроку не должен показывать fallback предыдущего.
</details>

## Задание — границы на экране урока

**Дано.** Экран урока RN Academy:

- шапка с названием и кнопкой «назад»;
- плеер видео (нативный компонент, бывают ошибки рендера из-за некорректных данных урока);
- текст урока;
- блок «Заметки» с полем ввода и кнопкой «Сохранить»;
- блок «Следующие уроки» (рекомендации, данные из отдельного запроса).

Сейчас границ нет нигде.

**Требуется.**

1. Расставить границы и обосновать каждую: что пропадёт при ошибке и что останется.
2. Реализовать границу с fallback «Повторить», сбрасываемую ключом и при смене урока.
3. Для каждого из пяти видов ошибок из вопроса 1 сказать, что увидит пользователь после расстановки.
4. Решить, какие асинхронные ошибки довести до границы, а какие обработать на месте.

---

<details>
<summary>Разбор</summary>

**1. Расстановка.**

```
App
└── ErrorBoundary (корень) — экран «Что-то пошло не так» + перезапуск
    └── Navigator
        └── LessonScreen
            ├── Header                              — вне границ экрана: «назад» работает всегда
            └── ErrorBoundary (содержимое экрана)   — fallback «Не удалось открыть урок» + повтор
                ├── ErrorBoundary (плеер)           — fallback «Видео недоступно», текст урока остаётся
                │   └── Player
                ├── LessonText
                ├── NotesBlock                      — без отдельной границы: ошибки сохранения обрабатываются на месте
                └── ErrorBoundary (рекомендации)    — fallback: блок просто не показывается
                    └── NextLessons
```

- **корень** — последний рубеж: вместо закрытия приложения экран с перезапуском;
- **содержимое экрана** — ошибка в тексте урока или в данных урока заменяет содержимое, шапка с «назад» остаётся;
- **плеер** — частая и независимая причина ошибок; урок полезен и без видео;
- **рекомендации** — полностью независимы; при ошибке блок исчезает (и ошибка уходит в отчёты);
- **заметки** — без своей границы: ошибка в их рендере — повод показать fallback экрана, а ожидаемые ошибки (сохранение) обрабатываются явно. Кроме того, повтор через ключ уничтожил бы введённый текст — его стоит хранить выше, если граница всё же нужна.

**2. Граница с повтором.**

```jsx
class ErrorBoundary extends Component {
  state = { error: null };
  static getDerivedStateFromError(error) { return { error }; }
  componentDidCatch(error, info) { reportError(error, { componentStack: info.componentStack }); }
  render() {
    if (this.state.error) return this.props.fallback({ error: this.state.error });
    return this.props.children;
  }
}

function LessonContentBoundary({ lessonId, children }) {
  const [attempt, setAttempt] = useState(0);
  return (
    <ErrorBoundary
      key={`${lessonId}:${attempt}`}
      fallback={() => (
        <View>
          <Text>Не удалось открыть урок</Text>
          <Button title="Повторить" onPress={() => setAttempt((a) => a + 1)} />
        </View>
      )}
    >
      {children}
    </ErrorBoundary>
  );
}
```

Ключ из `lessonId` и номера попытки: смена урока сбрасывает границу (fallback прошлого урока не показывается на новом), «Повторить» пересоздаёт поддерево — повторный рендер, эффекты, загрузка.

**3. Что увидит пользователь.**

| Ошибка | Результат |
|---|---|
| A: рендер `LessonText` | fallback содержимого экрана с повтором; шапка работает |
| A: рендер `Player` | «Видео недоступно», текст урока и заметки на месте |
| B: тело эффекта в рекомендациях | блок рекомендаций исчезает, остальное работает |
| C: таймер в эффекте | граница не видит; ошибка уходит в глобальный обработчик RN; если она не обработана — по правилам `ErrorUtils` (10.6) |
| D: `await` в обработчике | unhandled rejection; UI не меняется; нужна обработка на месте |
| E: синхронная ошибка в `onPress` | граница не видит; глобальный обработчик; UI не меняется |

Последние три строки — главный вывод задания: расстановка границ **не закрывает** ошибки обработчиков и асинхронного кода.

**4. Асинхронные ошибки.**

- **загрузка урока** — до границы содержимого экрана: без урока экран бессмыслен, fallback с повтором уместен;
- **загрузка видео плеером** — нативный плеер сообщает об ошибке событием; это ожидаемый случай — состояние «видео недоступно» внутри плеера, без границы;
- **сохранение заметки** — на месте: тост и повтор, текст остаётся в поле. Fallback здесь уничтожил бы ввод пользователя;
- **загрузка рекомендаций** — на месте: блок не показывается; можно и до границы рекомендаций — результат тот же, но явная обработка понятнее.

**Вклад в проект (P3).** В RN Academy появляются границы на корне и на содержимом каждого экрана, отдельные границы у плеера и рекомендаций, fallback с повтором через ключ. Ошибка загрузки урока доводится до границы, ошибки сохранения обрабатываются на месте. В тестах компонентов P3 проверяется, что ошибка рендера плеера не убирает текст урока.
</details>
