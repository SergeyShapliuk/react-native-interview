# 2.2 Generics — theory

> 🟢 REFRESH. Задача урока — не объяснить синтаксис `<T>`, а зафиксировать, что именно параметр типа связывает и когда он не связывает ничего.

## Refresh

### Параметр типа связывает вход с выходом

**Type parameter (параметр типа)** — переменная уровня типов: имя, неизвестное на момент объявления функции или типа и получающее конкретное значение на момент использования.

Без него связь между аргументом и результатом описывается перечислением — по перегрузке на каждый тип элемента (`first(items: string[]): string`, `first(items: Lesson[]): Lesson`). Список закрыт: каждая новая сущность домена требует новой строки. Параметр типа заменяет перечисление утверждением «тип результата равен типу элемента»:

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}
```

Связь видна по сигнатуре: `T` встречается и в параметрах, и в возвращаемом типе. Если `T` стоит только в одном месте, связывать нечего — к этому вернёмся в конце раздела.

### Вывод параметра типа и явное указание

В большинстве вызовов параметр выводится из аргументов: `first([1, 2, 3])` даёт `T = number`, а в `first<string>(['a', 'b'])` указание избыточно — без него тип тот же.

Явно указывать приходится в двух случаях. Первый — выводить не из чего:

```ts
const [lesson, setLesson] = useState<Lesson | null>(null);
```

Из `null` компилятор вывел бы `null`, и `setLesson(nextLesson)` перестал бы компилироваться.

Второй — вывод формально успешен, но шире нужного: `toSet(['draft', 'published'])` даёт `Set<string>`, потому что литералы в массиве расширяются (2.1, базовые типы и вывод типов). Если нужен `Set<'draft' | 'published'>`, параметр указывается явно.

### `extends` — ограничение, не наследование

**Constraint (ограничение параметра типа)** — требование к тому, чем `T` разрешено быть; записывается через `extends`. Внутри тела функции ограничение определяет, что с `T` можно делать.

```ts
function size<T>(x: T): number { return x.length; }  // ошибка: length у T может не быть
function size<T extends { length: number }>(x: T): number { return x.length; } // ок
```

`extends` читается как «совместим с», а не «унаследован от класса». `T extends Lesson` допускает любой тип со всеми полями `Lesson` — объектный литерал, `interface`, класс, пересечение типов.

Ограничение не сужает результат: `size(['a'])` по-прежнему получает `T = string[]`. Этим ограниченный параметр отличается от аннотации `x: { length: number }`, после которой точный тип аргумента теряется.

### Значение параметра по умолчанию

Дефолт используется, когда вывести параметр не удалось и явно он не указан:

```ts
type ApiResult<T = unknown> = { data: T; status: number };
type Raw = ApiResult;           // data: unknown
type Typed = ApiResult<Lesson>; // data: Lesson
```

`unknown` как дефолт оставляет вызывающего обязанным сузить тип, `any` отменяет проверки; различие — в 2.4 (`unknown` vs `any`).

### Generic-функция и generic-тип

```ts
type Mapper<T, R> = (item: T) => R;                    // параметры задаются при упоминании типа
const toTitle: Mapper<Lesson, string> = (l) => l.title;

function map<T, R>(items: T[], fn: (x: T) => R): R[] { // параметры выводятся при вызове
  return items.map(fn);
}
```

У generic-типа параметры фиксируются там, где тип упоминают, — один раз. У generic-функции каждый вызов даёт свои `T` и `R`. Следствие: если нужен один хелпер для разных типов, параметризовать нужно функцию.

### Несколько параметров и связь между ними

Ценность нескольких параметров — в том, как они связаны. В `map` выше `R` выводится из возвращаемого значения колбэка, а результат объявлен как `R[]`. Связать параметры можно и ограничением:

```ts
function groupBy<T, K extends keyof T>(items: T[], key: K): Map<T[K], T[]> {
  // ... out.set(item[key], bucket)
}
```

`K extends keyof T` означает: `K` — не произвольная строка, а одно из имён полей `T`. **`keyof T`** — union литеральных типов ключей `T`; **`T[K]`** — тип значения поля `K`.

```ts
groupBy(lessons, 'status'); // Map<Lesson['status'], Lesson[]>
groupBy(lessons, 'statuz'); // ошибка: 'statuz' не является keyof Lesson
```

Обращение `item[key]` внутри тела компилятор принимает из-за ограничения: он знает, что `key` — существующее имя поля. С `K extends string` эта строка не скомпилировалась бы и её закрывали бы приведением типа — вместе с проверкой имени на вызове.

### Признак лишнего generic

Параметр типа, встречающийся в сигнатуре **один раз**, ничего не связывает. Два варианта:

```ts
function logEvent<T>(payload: T): void {}   // T только в параметре
function parse<T>(raw: string): T { }       // T только в результате
```

Первый записан сложнее, чем `payload: unknown`, при том же эффекте. Во втором `T` назначает вызывающий, а не выводит компилятор: это приведение типа, оформленное как параметризация. Разбор этого случая — ниже.

## RN relevance

### Обёртка над хранилищем: `getItem<T>`

```ts
async function getItem<T>(key: string): Promise<T | null> {
  const raw = await AsyncStorage.getItem(key);
  return raw ? (JSON.parse(raw) as T) : null;
}

const lesson = await getItem<Lesson>('current-lesson'); // Lesson | null
```

Вызывающий код обращается к `lesson.title` без ошибок компиляции. При этом `T` встречается только в возвращаемом типе — признак из предыдущего раздела. Внутри стоит `as T`, и в рантайме не проверяется ничего: `JSON.parse` вернёт то, что лежало в хранилище, включая запись от прошлой версии приложения с другим набором полей. Ломается это обещание не в месте чтения, а на экране, обратившемся к отсутствующему полю.

> **Не дублировать:** почему `as` ничего не проверяет и чем его заменить — урок 2.4; схема как единственный источник и типа, и рантайм-проверки — 2.12. Здесь фиксируется только место, где параметр типа перестаёт связывать.

### Функция запроса к API

У `function request<T>(path: string): Promise<T>` та же форма и то же свойство: `T` назначает вызывающий. Отличие в том, что сигнатуру можно сделать содержательной — если путь и тип ответа описаны в одной структуре, `T` выводится из аргумента.

> **Не дублировать:** типизация полиморфного API-слоя — урок 2.11; conditional types и `infer`, на которых она строится, — 2.10.

### Типизированный список и `renderItem`

Пропсы списка параметризованы типом элемента — случай, где `T` связывает два места:

```ts
type ListProps<T> = {
  data: readonly T[];
  renderItem: (info: { item: T; index: number }) => React.ReactElement | null;
};
```

`T` выводится из `data`, после чего `item` внутри `renderItem` типизирован — без аннотации в колбэке и без `any`. Следствие: если `data` пришло из функции, вернувшей `any[]`, `item` теряет типизацию тоже, и опечатка в имени поля внутри ячейки компилируется.

> **Не дублировать:** типизация собственного компонента списка целиком, включая `ref` и дефолтные пропсы, — урок 2.14.

### Хелпер выбора поля из доменной сущности

```ts
function pluck<T, K extends keyof T>(items: T[], key: K): T[K][] {
  return items.map((item) => item[key]);
}

pluck(lessons, 'title');    // string[]
pluck(lessons, 'duration'); // number[]
```

Один хелпер, точный тип результата на каждом вызове, опечатка в имени поля не компилируется. В RN-коде такие функции живут в слое домена и в селекторах для экрана: отобрать идентификаторы для префетча, собрать значения фильтра.

> **Не дублировать:** вынос такого хелпера в кастомный хук — урок 3.12; типизация возвращаемого значения хука — 2.14.

## Типичные заблуждения

**«Generic сам по себе делает код типобезопасным.»** Возникает из наблюдения, что после добавления `<T>` ошибки компиляции исчезают. Исчезновение ошибки и наличие гарантии — разные события: в `getItem<T>` ошибки нет именно потому, что внутри стоит `as T`. Проверка: посмотреть, откуда `T` берёт значение; если его назначает вызывающий и внутри есть приведение — проверки нет ни на одном шаге.

**«Параметр типа нужно указывать при каждом вызове.»** Берётся из других языков и из примеров документации, где параметр пишут явно для наглядности. Проверка: убрать `<...>` и посмотреть на выведенный тип — если он тот же, указание было шумом.

**«`T extends Lesson` означает наследование от класса `Lesson`.»** Возникает из значения `extends` в классах JavaScript. В позиции параметра типа это «совместим с»: подходит любой тип, в котором есть все поля `Lesson` нужных типов, независимо от способа объявления. Проверка: передать объектный литерал в функцию с таким ограничением — он подойдёт, хотя ничего не наследует.

**«Если функция параметризована, она что-то проверяет.»** Источник тот же, плюс слово «проверка типов», которое звучит как действие в рантайме. Параметры типа стираются при компиляции: в собранном бандле от `<T>` не остаётся ни одной инструкции. Проверка: положить в хранилище строку, прочитать её через `getItem<Lesson>` и обратиться к `.title` — компилятор молчал, рантайм упал.
