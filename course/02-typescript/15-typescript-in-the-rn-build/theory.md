# 2.15 TypeScript в сборке RN: что делает Babel и чего он не умеет — theory

> 🟡 DEEP DIVE. Семь углов разбора. Урок отвечает не на вопрос «как настроить TypeScript в RN» — а на вопрос, **что сборка делает с TypeScript-кодом и какие конструкции после неё ведут себя иначе, чем ожидает автор, читающий `tsc`**.

Весь вывод сборки в уроке получен прогоном `@react-native/babel-preset` 0.87 (форматирование выровнено для чтения), сообщения компилятора — `tsc` 5.9 и 7.0, которые на этих примерах ведут себя одинаково.

---

## 1. Что это

В RN-проекте с TypeScript работают два инструмента, и у них разные задачи.

**`tsc`** проверяет типы. В RN-проекте он ничего не генерирует: базовый конфиг включает `noEmit`, и компилятор запускается только ради проверки — в редакторе, скриптом, в CI (2.8).

**Babel** превращает TypeScript в JavaScript для бандла. Metro передаёт ему каждый файл графа, Babel-пресет React Native применяет к файлам `.ts` и `.tsx` плагин TypeScript, и тот **стирает** синтаксис типов: аннотации, `interface`, `type`, `declare`, импорты и экспорты типов. Проверки при этом нет никакой.

Разница не только в том, что Babel не проверяет. Он и **не может** проверить: Babel обрабатывает один файл за раз и не видит других файлов проекта. Для него `import { LessonDto } from './types'` — имя, пришедшее из другого модуля, и узнать, тип это или значение, неоткуда.

### Ключевая формулировка урока

> **Babel не компилирует TypeScript, а стирает его — по одному файлу, ничего не зная о соседних. Всё, что в TypeScript зависит от знания о другом файле, при такой сборке исчезает или ломается в рантайме; `isolatedModules` — это `tsc`, который заранее показывает такие места.**

Большая часть TypeScript от знания о соседних файлах не зависит: аннотацию можно стереть, не зная ничего, кроме самого файла. Проблемы дают несколько конструкций, где `tsc` при генерации кода **пользуется** информацией о типах из других файлов. Их немного, и они перечислены ниже.

## 2. Как это работает

### Что Babel делает с импортом, который используется только как тип

Правило плагина: если импортированное имя ни разу не использовано как значение — только в позициях типа или вообще нигде, — импорт удаляется. Если удалены все имена из объявления, исчезает объявление целиком.

```ts
import { LessonDto } from './types';
export const make = (): LessonDto => ({ id: '1', title: 't' });
```

```js
// в бандле
var make = () => ({ id: '1', title: 't' });
exports.make = make;
```

Строки `require('./types')` нет. Для модуля, в котором только типы, это правильно. Но если у модуля есть **побочный эффект** — инициализация, регистрация, полифил, — он не выполнится: файл никто не загрузил.

Импорт ради побочного эффекта без имён остаётся всегда:

```ts
import './polyfills';            // → require("./polyfills")
```

### Повторный экспорт типа

```ts
// api/index.ts
export { LessonDto } from './types';
```

Здесь у Babel нет даже использования, по которому можно судить. Он видит повторный экспорт имени из другого файла и обязан его сохранить — вдруг это значение:

```js
Object.defineProperty(exports, "LessonDto", {
  enumerable: true,
  get: function () { return _types.LessonDto; }
});
var _types = require("./types");
```

Получается геттер, возвращающий `undefined`, и загрузка модуля `./types`, которая не нужна. Сам по себе такой экспорт ничего не ломает — типы в рантайме никто не читает, — но это ровно то место, где `tsc` и Babel понимают код по-разному. Запись, которую Babel понимает однозначно, — `export type { LessonDto } from './types'`: она стирается целиком.

### `enum`

`enum` — единственная конструкция TypeScript (вместе с `namespace`), которая **порождает код**:

```ts
export enum Level { Easy, Hard }
export enum Status { Done = 'done', Todo = 'todo' }
```

```js
var Level = function (Level) {
  Level[Level["Easy"] = 0] = "Easy";
  Level[Level["Hard"] = 1] = "Hard";
  return Level;
}({});
var Status = function (Status) {
  Status["Done"] = "done";
  Status["Todo"] = "todo";
  return Status;
}({});
```

У числового `enum` есть обратное отображение: объект содержит и `Easy → 0`, и `0 → "Easy"`. Поэтому `Object.keys(Level)` — это `['0', '1', 'Easy', 'Hard']`, а не два значения. У строкового `enum` обратного отображения нет.

### `const enum` из своего файла

`tsc` при полной компиляции встраивает значения `const enum` в места использования: `Tab.Lessons` становится `"lessons"`, объекта в выходном коде нет. Чтобы встроить значение в другом файле, нужно знать, что в том файле объявлено, — то есть ровно то, чего Babel не знает.

Поэтому Babel поступает с `const enum` так же, как с обычным:

```ts
export const enum Tab { Lessons = 'lessons', Progress = 'progress' }
export const current = Tab.Lessons;
```

```js
var Tab = exports.Tab = function (Tab) {
  Tab["Lessons"] = "lessons";
  Tab["Progress"] = "progress";
  return Tab;
}({});
var current = exports.current = Tab.Lessons;
```

Объект в бандле есть, обращение — чтение свойства. Работает корректно, но ничего из того, ради чего пишут `const`, не происходит.

### Ambient `const enum` — объявленный только в типах

Ambient-объявление — это объявление в `.d.ts` или с `declare`: оно сообщает компилятору о значении, которое где-то существует, и само кода не порождает (2.9). Если `const enum` объявлен **только** в типах, в JavaScript его нет вовсе: `tsc` при полной компиляции встроил бы значения, и объект был бы не нужен. Babel встроить не может — и оставляет обращение к тому, чего нет.

Случай первый — `const enum` в типах библиотеки:

```ts
// node_modules/video-lib/index.d.ts
export declare const enum Quality { Auto = 0, High = 1 }

// player.ts
import { Quality } from 'video-lib';
export const q = Quality.High;
```

```js
var _videoLib = require("video-lib");
var q = exports.q = _videoLib.Quality.High;
```

В JavaScript библиотеки `Quality` не экспортируется, `_videoLib.Quality` — `undefined`, и чтение `.High` бросает `TypeError` (в Hermes — `Cannot read property 'High' of undefined`).

Случай второй — глобальное объявление в своём `.d.ts`:

```ts
// haptics.d.ts
declare const enum HapticKind { Light = 'light', Heavy = 'heavy' }

// feedback.ts
export const kind = HapticKind.Light;
```

```js
var kind = exports.kind = HapticKind.Light;   // ReferenceError: HapticKind is not defined
```

В обоих случаях `tsc` без `isolatedModules` молчит: с точки зрения компилятора код корректен, значения он встроил бы сам. Падение случается на устройстве, в момент выполнения модуля, — то есть при первом открытии экрана, который его импортирует.

### `namespace` и поля классов с `declare`

Пресет React Native включает в плагине TypeScript поддержку `namespace`: обычный `namespace` превращается в объект, `declare namespace` стирается. Слияние одноимённых `namespace` из разных файлов при пофайловой сборке невозможно по определению.

Отдельный случай — поле класса с модификатором `declare`:

```ts
export class Repo {
  declare cache: Map<string, string>;
}
```

Сборка этого файла падает с ошибкой `The 'declare' modifier is only allowed when the 'allowDeclareFields' option of @babel/plugin-transform-flow-strip-types or @babel/preset-flow is enabled`. Пресет React Native применяет плагин Flow ко **всем** файлам, включая `.ts`, и делает это первым, а опция `allowDeclareFields` в пресете не включена. Ошибка честная — сборка падает сразу, а не на устройстве, — но её текст про Flow сбивает с толку в проекте, где Flow нет. Parameter properties (`constructor(private readonly base: string)`) собираются без проблем.

### `isolatedModules`: проверка «собирается ли это по одному файлу»

`isolatedModules` не меняет генерацию кода — в RN её и нет, `noEmit`. Флаг заставляет `tsc` сообщать о конструкциях, которые нельзя корректно собрать, глядя на один файл:

```
export { LessonDto } from './types';
  TS1205: Re-exporting a type when 'isolatedModules' is enabled requires using 'export type'.

export const q = Quality.High;
  TS2748: Cannot access ambient const enums when 'isolatedModules' is enabled.
```

То есть `isolatedModules` — это `tsc`, который смотрит на код глазами Babel. Базовый конфиг React Native (`@react-native/typescript-config` 0.87) этот флаг включает — именно ради мест из предыдущих разделов.

`const enum` из своего `.ts`-файла при `isolatedModules` ошибкой не считается: Babel соберёт его как обычный `enum`, и код будет работать.

### `verbatimModuleSyntax`: что написано, то и остаётся

`verbatimModuleSyntax` строже. Он требует, чтобы каждый импорт и экспорт типа был помечен `type` явно, — и включает все проверки `isolatedModules`:

```
import { LessonDto } from './types';
  TS1484: 'LessonDto' is a type and must be imported using a type-only import
          when 'verbatimModuleSyntax' is enabled.
```

Смысл флага — убрать из кода решения, которые инструмент принимает сам. Без него читатель строки `import { LessonDto, fetchLessons } from './api'` не знает, что из этого останется в бандле, — это решает Babel по использованию. С флагом граница видна в тексте: `import { type LessonDto, fetchLessons } from './api'`.

Важная оговорка: на поведение Babel-сборки этот флаг **не влияет**. `tsc` при `verbatimModuleSyntax` сохранил бы `import { type LessonDto } from './types'` как импорт ради побочного эффекта; Babel-пресет React Native удаляет такой импорт целиком — так же, как и раньше. Если модуль нужен ради побочного эффекта, это пишется отдельной строкой `import './i18n'`, и только эта запись надёжна при любой сборке.

## 3. Почему это важно

Урок 2.8 закончился выводом: приложение с ошибками типов собирается и работает, потому что Metro типы не проверяет. Этот урок добавляет вторую половину: **приложение без ошибок типов может падать из-за того, как его собрали**.

Ambient `const enum` из типов библиотеки — самый наглядный случай. `tsc` без `isolatedModules` не видит проблемы, редактор не видит проблемы, сборка проходит, и экран, использующий значение, падает у пользователя при первом открытии. Модуль с инициализацией, импортированный только ради типа, не падает вовсе — он просто не выполняется, и приложение работает без переводов или без зарегистрированного обработчика.

Общее у этих случаев одно: автор читает код так, как его понял бы `tsc`, а исполняется код так, как его понял Babel. Пока конструкций, где они расходятся, в проекте нет, разница невидима. `isolatedModules` превращает это расхождение из рантайм-сюрприза в ошибку проверки типов, и поэтому выключать его ради тишины — значит выключать единственный сигнал.

## 4. Где это в React Native

### Базовый конфиг

`tsconfig.json` проекта наследует `@react-native/typescript-config`, где включены `noEmit`, `isolatedModules` и `strict`, а `verbatimModuleSyntax` — нет. Как и в 2.8, проверять нужно свой проект: `tsc --showConfig` покажет, не выключил ли кто-то `isolatedModules` локально.

### Типы библиотек с `const enum`

Чаще всего ambient `const enum` приходит не из своего кода, а из `.d.ts` зависимости: библиотека, которая сама собиралась `tsc`, объявила перечисление как `const enum`, и в её JavaScript этого объекта нет. С `isolatedModules` такое место даёт TS2748 сразу после обновления зависимости. Правка — передать литеральное значение, которое стоит за членом перечисления, или использовать объект, если библиотека экспортирует его в рантайме; это видно в её JavaScript, а не в `.d.ts`.

### Barrel-файлы

Файл `index.ts`, собирающий экспорты фичи, — главное место повторного экспорта типов. Каждый `export { X } from './y'`, где `X` — тип, даёт TS1205 и геттер в бандле. Запись с разделением: `export type { LessonDto } from './types'` отдельно от `export { fetchLessons } from './client'`. Влияние barrel-файлов на граф модулей и hot reload — 1.10.

### Модуль с побочным эффектом и типами

Типичный пример — модуль локализации: он инициализирует библиотеку переводов при загрузке и заодно экспортирует тип `Locale`. Если корневой компонент импортирует из него только тип, Babel удалит импорт, и инициализация не выполнится. Работает это обычно случайно — пока какой-то другой файл импортирует из того же модуля значение. Исправление — явный `import './i18n'` в точке входа.

### Jest

Шаблон RN-проекта собирает тесты через `babel-jest` с тем же пресетом, поэтому тест, который выполняет код с ambient `const enum`, падает так же, как устройство. Если же тесты собираются инструментом, использующим полную информацию о типах (`ts-jest` без `isolatedModules`), значения `const enum` встраиваются, и тест проходит там, где приложение падает. Трансформация кода в тестах должна совпадать с трансформацией в сборке — подробнее в блоке 11.

> **Не дублировать:** Metro, resolver, кэш трансформации и профили сборки — 4.4; алиасы путей и их синхронизация между инструментами — 8.6; `tsc --noEmit` как шаг пайплайна — блок 10.

## 5. Типичные ошибки

**«Сборка прошла — значит, `tsc` согласен».** Сборка не запускает `tsc` вовсе (2.8). Более того, часть кода, с которым `tsc` полностью согласен, в сборке ведёт себя иначе. Единственный источник ответа «типы в порядке» — `tsc --noEmit` с конфигом проекта.

**Выключить `isolatedModules`, потому что после обновления библиотеки появились десятки ошибок.** Ошибки TS2748 и TS1205 — не стилистические замечания: каждая из них указывает на место, которое в бандле ведёт себя иначе, чем в редакторе. Выключение флага не меняет бандл — оно убирает единственное предупреждение.

**`const enum` «ради производительности».** Аргумент про встраивание значений относится к сборке `tsc`. В Babel-сборке `const enum` из своего файла — обычный объект с чтением свойства, а ambient `const enum` — падение. Выигрыша нет, риск есть.

**`Object.keys` или `Object.values` у числового `enum` для построения списка.** Обратное отображение удваивает элементы: выбор уровня сложности показывает четыре варианта — `0`, `1`, `Easy`, `Hard`. Строковый `enum` этим не страдает, объект `as const` — тоже.

**Повторный экспорт типов через barrel без `export type`.** Без `isolatedModules` проходит молча; в бандле — геттеры, возвращающие `undefined`, и лишняя загрузка модулей.

**Рассчитывать на импорт типа как на загрузку модуля.** Импорт, все имена которого используются как типы, удаляется. Побочный эффект модуля зависит тогда от того, импортирует ли его кто-то ещё ради значения, — то есть от несвязанного кода.

**`declare` у поля класса.** Сборка падает с ошибкой про Flow-плагин, хотя Flow в проекте нет. Обычно поле с `declare` можно заменить объявлением с `!` или инициализацией в конструкторе.

## 6. Trade-offs

### Union литералов, объект `as const` и `enum`

| Вариант | Что в бандле | Перебор значений | Подводные камни |
|---|---|---|---|
| union литералов `'lessons' \| 'progress'` | ничего | нет объекта — список значений не получить | при переименовании правятся все литералы (компилятор покажет где) |
| объект `as const` и тип из него | один объект | `Object.values` даёт ровно значения | две записи: объект и выведенный тип |
| строковый `enum` | объект | `Object.values` даёт значения | порождает код; строковый литерал не присваивается в тип `enum` |
| числовой `enum` | объект с обратным отображением | `Object.keys` и `Object.values` удвоены | то же плюс обратное отображение |
| `const enum` | в Babel — объект, как у обычного | как у обычного | ambient-вариант падает в рантайме |

Вариант по умолчанию для RN-проекта — объект `as const` и тип, выведенный из него:

```ts
export const Tab = { Lessons: 'lessons', Progress: 'progress' } as const;
export type Tab = (typeof Tab)[keyof typeof Tab];   // 'lessons' | 'progress'
```

Он даёт то же, что строковый `enum`, — объект для перебора и имя для типа, — но ведёт себя одинаково при любой сборке и сравнивается с обычными строками без приведения. Union литералов без объекта — когда перебор не нужен. Свойство строкового `enum`, которое иногда называют преимуществом, — нельзя передать `'lessons'` туда, где ждут `Tab.Lessons`, — номинальность ценой рантайм-кода; если она действительно нужна, её дают брендированные типы (2.16).

### `isolatedModules` против `verbatimModuleSyntax`

`isolatedModules` ловит только то, что ломается при пофайловой сборке, и не требует правок там, где Babel и так справится. `verbatimModuleSyntax` требует пометить каждый импорт типа — на существующем проекте это сотни правок, хотя и механических (их делает автоисправление линтера или компилятора). Выигрыш — читаемость: по строке импорта видно, что останется в бандле, а код одинаково понимается любым инструментом, который транспилирует пофайлово. Для нового проекта цена почти нулевая; для существующего — отдельное механическое изменение, которое не стоит смешивать с продуктовыми задачами.

### Babel как транспилятор

Пофайловая обработка — не недостаток Babel, а условие, на котором держится скорость Metro: каждый файл трансформируется независимо и кэшируется отдельно, и изменение одного файла не требует знания о графе (1.10, 4.4). Цена этой скорости — отказ от генерации кода по типам. Отсюда правило: конструкции, которым для генерации нужна информация о типах, в RN-проекте не используются, и `isolatedModules` следит за этим автоматически.
