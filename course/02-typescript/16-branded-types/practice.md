# 2.16 Брендированные типы: номинальность в структурной системе — practice

## Проверка понимания

Вопросы уровня собеседования. Правильный ответ требует сказать, **где выдаётся бренд и что он гарантирует**, а не показать синтаксис пересечения.

---

**1. Почему `type LessonId = string` не мешает передать `CourseId`?**

<details>
<summary>Ответ</summary>

Потому что `type` объявляет **псевдоним**, а не новый тип. `LessonId` и `CourseId` — два имени одного `string`, и TypeScript сравнивает типы по структуре, не по имени. Для компилятора вызов `loadLesson(courseId)` — передача строки туда, где ждут строку.

Чтобы типы стали различимы, у них должна различаться структура. Бренд добавляет к `string` свойство-метку, которой в рантайме нет: `string & { readonly [brand]: 'LessonId' }`. Теперь у `CourseId` метка другая, и присваивание не проходит.

**Ответ «надо объявить через `interface`»** вскрывает перенос номинальности из других языков. `interface` в TypeScript тоже сравнивается структурно (2.6); примитив им к тому же не опишешь.

**Ответ «TypeScript проверит по имени, если включить `strict`»** вскрывает ожидание, что строгость меняет модель сравнения. Ни один флаг не делает систему типов номинальной.

**Ответ «можно сделать `LessonId` классом»** — рабочая альтернатива, но с ценой, которую ответ не называет: объект вместо примитива не проходит JSON и нативную границу без преобразования и ломает сравнение по `===` (1.2, 1.12).
</details>

---

**2. Где в приложении должен находиться единственный способ создать `LessonId`?**

<details>
<summary>Ответ</summary>

**На границе, там, где значение проверяется**, — в модуле конструкторов или в схеме, через которую проходят внешние данные. Конкретно: схема ответа сервера (поле `id` — брендированная схема), разбор параметров deep link и push, чтение из хранилища. Всё остальное приложение `LessonId` не создаёт, а получает.

Почему именно там: бренд гарантирует ровно то, что проверило место, где его выдали. Если `as LessonId` можно написать где угодно, то значение типа `LessonId` может оказаться чем угодно, и бренд превращается в аннотацию, которой нельзя верить. Если выдача одна и она проверяет формат, то `LessonId` в сигнатуре означает «проверенный идентификатор урока» во всём коде.

Практический признак правильного устройства: поиск по `as LessonId` находит один файл, а тестовые данные создаются через те же конструкторы или одну фабрику.

**Ответ «в типах домена, рядом с `type Lesson`»** путает место объявления типа с местом создания значения. Объявить можно где угодно; важно, где пишется утверждение.

**Ответ «в компоненте, где известно, что это урок»** вскрывает подмену проверки знанием автора. Знание автора не переходит к следующему, кто вызовет тот же код с другими данными.
</details>

---

**3. Что останется от бренда после записи в хранилище и чтения обратно?**

<details>
<summary>Ответ</summary>

Ничего. Бренда нет в рантайме и до записи: после сборки конструктор — это `s => s`. В хранилище уходит обычная строка, обратно приходит обычная строка, а `JSON.parse` возвращает `any`.

Опасность в последнем. `const saved: Progress = JSON.parse(raw)` компилируется, и в `saved` «появляются» `LessonId` и `DurationMs` без всякой проверки. Тип записи в коде описывает модель текущей версии, данные записаны когда-то раньше (2.13). Поэтому чтение из хранилища — граница: значение разбирается той же схемой, и бренды выдаются заново.

**Ответ «бренд сохранится, потому что TypeScript запомнил тип»** вскрывает смешение типа с данными. Тип существует только при компиляции; у прочитанной строки нет памяти о том, каким типом она была.

**Ответ «строка та же, значит, бренд можно вернуть через `as`»** — частая правка, которая выдаёт квитанцию без проверки. Строка та же только до первого обновления приложения, сменившего формат идентификатора, или до первой порчи записи.
</details>

---

**4. Функция принимает `lessonId: LessonId`. Что она может считать гарантированным, а что — нет?**

<details>
<summary>Ответ</summary>

Гарантировано то, что проверил конструктор: строка непустая, имеет формат идентификатора урока — например, префикс `l_` и допустимые символы. И гарантировано, что это **не** идентификатор курса и не произвольная строка из кода — при условии, что `as LessonId` нигде, кроме конструктора, не пишется.

Не гарантировано:

- **существование урока.** Корректный по форме идентификатор может указывать на удалённый урок; ответ на это даёт только сервер;
- **права доступа.** Чужой урок имеет тот же формат идентификатора (2.12: проверка формы не проверяет смысл);
- **актуальность.** Значение, полученное до обновления приложения или из восстановленного состояния навигации, могло быть брендировано при чтении без разбора.

**Ответ «гарантировано, что урок существует»** вскрывает смешение формы с фактом. Бренд — свойство значения, а не состояния системы.

**Ответ «ничего не гарантировано, бренд — только тип»** вскрывает обратную крайность. Верно, что в рантайме бренда нет, но гарантия существует — она переносится из места выдачи. Без единственного конструктора она действительно пропадает.
</details>

## Задание — бренды в домене RN Academy

**Дано.** Модуль домена RN Academy и экран урока. Всё компилируется. После рефакторинга экрана урока пришли жалобы: экран открывается с сообщением «урок не найден»; сохранённая позиция видео после возобновления сбивается к началу; оставшееся время урока показывается огромным отрицательным числом.

```ts
// domain/types.ts
export type Lesson = { id: string; courseId: string; title: string; durationMin: number };

// api/lessons.ts
export declare function loadLesson(lessonId: string): Promise<Lesson>;
export declare function saveProgress(lessonId: string, positionMs: number): Promise<void>;

// navigation/types.ts
export type RootParamList = {
  Course: { courseId: string };
  Lesson: { lessonId: string; courseId: string };
};

// screens/LessonScreen.tsx
function LessonScreen({ route }: LessonScreenProps) {
  const { lessonId, courseId } = route.params;
  const lesson = useLesson(courseId);                          // внутри — loadLesson
  const [positionMs, setPositionMs] = useState(0);

  const onProgress = (sec: number) => {                        // плеер сообщает секунды
    setPositionMs(sec);
    saveProgress(lessonId, sec);
  };
  const remainingMs = lesson.durationMin - positionMs;
  // ...
}

// linking.ts — обработчик ссылки rnacademy://course/:courseId/lesson/:lessonId
export function openFromLink(url: string) {
  const [, courseId, , lessonId] = new URL(url).pathname.split('/').filter(Boolean);
  navigate('Lesson', { lessonId, courseId });
}
```

Идентификаторы имеют формат `l_<буквы и цифры>` для урока и `c_<буквы и цифры>` для курса. Сервер отдаёт урок с полями `id`, `course_id`, `title`, `duration_min`.

**Требуется.**

1. Ввести бренды `LessonId`, `CourseId` и `DurationMs` в модуле домена: конструкторы со схемой на границе, сигнатуры API и навигации на брендах.
2. Перечислить места, где компилятор начал сообщать о перепутанных значениях, и связать каждое с жалобой.
3. Найти места, где бренд пришлось бы ставить через `as`, и каждое объяснить или убрать.
4. Сказать, что бренды в этом модуле не закрывают.

<details>
<summary>Разбор</summary>

**1. Бренды и конструкторы.**

Запись — zod 4; в valibot то же самое даёт `v.pipe(v.string(), v.regex(…), v.brand('LessonId'))`.

```ts
// domain/ids.ts — единственный модуль, где выдаются бренды
export const LessonId = z.string().regex(/^l_[a-z0-9]+$/).brand<'LessonId'>();
export type LessonId = z.infer<typeof LessonId>;

export const CourseId = z.string().regex(/^c_[a-z0-9]+$/).brand<'CourseId'>();
export type CourseId = z.infer<typeof CourseId>;

export const DurationMs = z.number().int().nonnegative().brand<'DurationMs'>();
export type DurationMs = z.infer<typeof DurationMs>;

export const minutesToMs = (min: number): DurationMs => DurationMs.parse(min * 60_000);
export const secondsToMs = (sec: number): DurationMs => DurationMs.parse(Math.round(sec * 1000));
```

```ts
// domain/lesson.ts
const lessonDtoSchema = z.object({
  id: LessonId,
  course_id: CourseId,
  title: z.string(),
  duration_min: z.number().int().nonnegative(),
});
type LessonDto = z.infer<typeof lessonDtoSchema>;

export type Lesson = { id: LessonId; courseId: CourseId; title: string; durationMs: DurationMs };

const toLesson = (dto: LessonDto): Lesson => ({
  id: dto.id,
  courseId: dto.course_id,
  title: dto.title,
  durationMs: minutesToMs(dto.duration_min),   // перевод единиц — на границе, один раз
});

export async function loadLesson(lessonId: LessonId): Promise<Lesson> {
  return toLesson(lessonDtoSchema.parse(await request(`/lessons/${lessonId}`)));
}
export declare function saveProgress(lessonId: LessonId, position: DurationMs): Promise<void>;
```

```ts
// navigation/types.ts
export type RootParamList = {
  Catalog: undefined;
  Course: { courseId: CourseId };
  Lesson: { lessonId: LessonId; courseId: CourseId };
};
```

Обратите внимание на `toLesson`: бренды идентификаторов приходят из схемы без единой строки кода, а длительность меняет единицы — минуты сервера становятся миллисекундами домена. После этого в домене нет поля, единицы которого нужно угадывать по имени.

**2. Что перестало компилироваться.**

| Место | Сообщение (сокращённо) | Жалоба |
|---|---|---|
| `useLesson(courseId)` → `loadLesson(courseId)` | `CourseId` не присваивается в `LessonId` | «урок не найден»: запрос шёл по идентификатору курса, и сервер отвечал 404. Если бы форматы идентификаторов совпадали (например, числа), запрос вернул бы **чужой** урок — и дефект было бы ещё труднее заметить |
| `saveProgress(lessonId, sec)` | `number` не присваивается в `DurationMs` | «позиция сбивается к началу»: сохранялись секунды как миллисекунды, 125 секунд превращались в 0,125 секунды |
| `setPositionMs(sec)` (при `useState<DurationMs>`) | `number` не присваивается в `DurationMs` | та же причина на экране |
| `lesson.durationMin - positionMs` | у `Lesson` больше нет `durationMin` | «огромное отрицательное время»: минуты минус миллисекунды |
| `navigate('Lesson', { lessonId, courseId })` в `openFromLink` | `string` не присваивается в `LessonId` | жалобы пока нет: ссылка с испорченным идентификатором открывала пустой экран |

Исправленные места:

```ts
const lesson = useLesson(lessonId);
const [positionMs, setPositionMs] = useState<DurationMs>(DurationMs.parse(0));   // и начальное значение — через конструктор

const onProgress = (sec: number) => {
  const position = secondsToMs(sec);
  setPositionMs(position);
  saveProgress(lessonId, position);
};
const remainingMs = lesson.durationMs - positionMs;   // number: разность — уже не длительность
```

`remainingMs` остаётся `number`, и это правильно: разность длительности и позиции может быть отрицательной (например, при рассинхронизации плеера), а `DurationMs` по определению неотрицательна. Если значение нужно как длительность, его пропускают через `DurationMs.parse` или явно ограничивают снизу.

```ts
export function openFromLink(url: string) {
  const [, rawCourse, , rawLesson] = new URL(url).pathname.split('/').filter(Boolean);
  const courseId = CourseId.safeParse(rawCourse);
  const lessonId = LessonId.safeParse(rawLesson);
  if (!courseId.success || !lessonId.success) {
    report('linking: неверная ссылка на урок', { url });
    return navigate('Catalog');
  }
  navigate('Lesson', { lessonId: lessonId.data, courseId: courseId.data });
}
```

Ветка «ссылка не разобралась» появилась принудительно: без неё вызов `navigate` не компилируется.

Все перечисленные ошибки воспроизводятся `tsc` на этом коде; исправленный код компилируется.

**3. Где понадобился бы `as`.**

- **В модуле конструкторов — нигде.** Схема выдаёт бренд сама: `as` спрятан внутри `.brand()`, после проверки формата.
- **Тестовые данные.** Фикстура `{ id: 'l_1', courseId: 'c_1', … }` перестаёт компилироваться как `Lesson`. Правильное место — одна тестовая фабрика, которая строит данные через те же схемы (`LessonId.parse('l_1')`), а не `as` в каждом тесте: тогда фикстура с неверным форматом упадёт в тесте, а не пройдёт молча.
- **Восстановленное состояние навигации.** Библиотека навигации возвращает параметры уже типизированными по `ParamList`, и формально `as` не нужен — но и проверки нет. Это не место для `as`, а место, где бренд в типе — утверждение без проверки (2.13). Решение — версионировать состояние навигации и сбрасывать его при несовпадении; механика — 4.16.
- **`JSON.parse` при чтении прогресса из хранилища.** Присваивание результата в тип с брендами компилируется без `as`, потому что `JSON.parse` возвращает `any`. Это самый незаметный обход: исправляется разбором записи схемой при чтении.

Итог: явный `as` к бренду в коде не нужен нигде. Два места, где бренд появляется без проверки неявно, — `any` из `JSON.parse` и состояние навигации, — найдены и закрыты разбором либо записаны как граница.

**4. Что бренды не закрывают.**

- **Существование и права.** `LessonId` в правильном формате может указывать на удалённый или чужой урок — это проверяет сервер.
- **Значения за пределами модуля.** Нативный плеер по-прежнему сообщает секунды обычным `number`; бренд появляется только после `secondsToMs` в обработчике. Если завтра библиотека плеера начнёт отдавать миллисекунды, компилятор этого не заметит — контракт нативной стороны описан `.d.ts` (2.9).
- **Арифметику.** Любая операция над `DurationMs` возвращает `number`; бренд защищает от смешения на входе в функции, а не внутри вычислений.

**Вклад в проект (P2).** В домене RN Academy появился модуль идентификаторов и единиц: `LessonId`, `CourseId`, `DurationMs` и конвертеры единиц объявлены схемами с `.brand()`, и только этот модуль выдаёт бренды. Схема ответа урока из 2.12 использует их как поля, `toLesson` переводит минуты сервера в миллисекунды домена, сигнатуры API и `ParamList` построены на брендах. Зафиксированы правила проекта: `as` к бренду запрещён вне модуля идентификаторов; тестовые данные создаются фабрикой через те же схемы; любое значение, прошедшее через JSON, хранилище или нативный модуль, разбирается заново. Перечень мест, где бренды выдаются, становится частью карты границ в 2.13.
</details>
