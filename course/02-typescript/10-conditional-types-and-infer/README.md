## Цель

Читать типы, построенные на условных конструкциях, и выводить тип из типа там, где иначе пришлось бы описать его дважды.

## Что внутри

`T extends U ? A : B` как вычисление на типах · дистрибутивность: почему условный тип над голым параметром раскладывает union по членам и как отключить это через `[T] extends [U]` · `infer` и позиции, где он допустим; объединение кандидатов в ковариантных позициях и пересечение в контравариантных · из чего собраны `ReturnType`, `Parameters`, `Awaited`, `NonNullable` · рекурсивные типы и предел глубины инстанцирования · где это в RN: вывод `route.params` из `ParamList`, типы схем валидации, клиенты данных · ошибки: сложный тип вместо безопасного дублирования, потерянная и лишняя дистрибутивность, тип, который компилируется минуту · trade-offs: читаемость, время проверки, качество сообщений об ошибках для всех пользователей типа.

## Ключевая формулировка урока

**Условный тип — это вычисление, которое выполняет компилятор. Для RN-разработчика ценность этого урока в первую очередь в чтении чужих вычислений: сообщение об ошибке при неверных параметрах экрана есть результат такого вычисления, и прочитать его — единственная альтернатива правке наугад.**

Отсюда критерий, по которому в уроке принимается решение писать свой условный тип: **дублирование плохо, когда два описания расходятся молча.** Если расхождение немедленно даёт ошибку компиляции, дублирование дешевле вычисления.
