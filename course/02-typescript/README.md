## Цель блока

Использовать систему типов как инструмент проектирования, а не как аннотации поверх готового кода. Главный сдвиг: тип описывает допустимые состояния системы, и невозможные комбинации не должны компилироваться.

Урок 2.9 — ключевой для курса: именно границы (ответ сервера, параметры экрана, контракт нативного модуля) — те места, где TypeScript даёт ложную уверенность, потому что типы там не проверяются в рантайме.

## Что должно быть получено

- Описываю состояние типом так, что невозможные комбинации не компилируются.
- Вывожу типы API-слоя из одного источника, а не поддерживаю две копии.
- Понимаю, где тип — это гарантия, а где — только надежда (границы системы).
- Знаю, что именно включает каждый флаг `strict` и в каком порядке их включать при миграции.

## Checkpoint

Дан экран, получающий данные с сервера и передающий часть из них на следующий экран через параметры навигации. Типизировать путь данных так, чтобы: ответ сервера валидировался на границе, параметры экрана были выведены из одного источника, а не описаны вручную, и невалидное состояние экрана (например, `loading` вместе с `data`) не компилировалось.
