## Ключевая формулировка урока

**Тип — это утверждение о коде, а не о данных. На границе его не проверяет никто.**

Урок 2.12 дал инструмент; этот урок отвечает, к скольким местам его применять. Главная работа здесь — составить перечень: граница, которую не назвали, не может быть ни закрыта, ни осознанно оставлена открытой. Из четырёх состояний границы дефектом считается одно — «не рассмотрена».

## Три границы, специфичные для мобильного приложения

Они же чаще всего не рассматриваются вовсе, потому что данные в них приходят **из другого времени или из другого языка**, а компилятор уверен так же, как если бы значение пришло из соседней функции:

- **восстановление навигационного состояния** — `ParamList` описывает текущую версию кода, состояние записано прошлым запуском, возможно под предыдущей версией приложения;
- **хранилище после обновления приложения** — тип описывает модель, которая есть сейчас, данные записаны моделью, которой уже нет; исправить запись может только код приложения;
- **колбэк нативного модуля** — контракт описан в `.d.ts`, нативная сторона написана на другом языке, и сверить одно с другим не может ни компилятор, ни сборка.
