## Что внутри

Где две записи взаимозаменяемы и где заканчивается «форма объекта» · declaration merging как свойство `interface` и `Duplicate identifier` как ответ `type` на то же действие · union, кортежи, mapped и conditional types — только `type` · `extends` против пересечения: конфликт свойств даёт ошибку в месте объявления в первом случае и `never` в месте использования во втором · structural typing и `implements`, который не меняет тип класса · сообщения об ошибках и стоимость проверки длинных цепочек `&` · где это в RN: `ReactNavigation.RootParamList`, тип темы, `ProcessEnv` против внутренних типов приложения и DTO · ошибки: «interface быстрее» без уточнения, `&` там, где нужна проверка, declaration merging для `type`, публичный тип модуля как `type` без решения · trade-offs: открытость против контроля, выразительность против читаемости ошибок, единое правило против выбора по случаю.

## Ключевая формулировка урока

> **`interface` — это открытое объявление, `type` — закрытое. Выбор между ними есть ответ на вопрос, вправе ли кто-то снаружи дополнить этот тип.**

Всё остальное — выразительность, сообщения об ошибках, стоимость проверки — следствия либо второстепенные детали. Отсюда рабочее правило: `interface` — для контрактов, которые предполагается расширять снаружи; `type` — для всего остального. Это **соглашение проекта, а не правило языка**: TypeScript не придаёт `interface` смысла «публичный API», и в чужом коде он сплошь и рядом описывает внутренние структуры.
