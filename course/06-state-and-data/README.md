# 06 — State Management & Data (client state)

**Prerequisites:** [03 — React](../03-react/), [05 — Performance](../05-performance/)

## Цель блока

Научиться решать, где живёт каждая единица состояния, и платить за это осознанно. Блок отвечает за **клиентское состояние и управление состоянием приложения**. Серверные данные, кэш и синхронизация — блок [07](../07-networking/).

Вторая половина — вводный урок блока 07 «Server State как распределённые данные», где та же граница рассматривается со стороны сервера. ## Что должно быть получено

- Обосновываю, где лежит каждая единица состояния, и называю цену размещения.
- Нормализую данные и объясняю выигрыш в конкретных числах, а не «так правильнее».
- Переживаю изменение схемы персистентного стейта без потери данных у пользователей.
- Вижу селектор, который рендерит половину экрана, и исправляю его.

## Checkpoint

Дан экран: черновик формы, который не должен теряться при переходе между экранами; список сущностей, пришедших с сервера; флаг «показать подсказку», который должен помниться между запусками; результат поиска по серверу. Разложить все четыре единицы данных: где хранится, почему именно там, что произойдёт при перезапуске приложения, при потере сети, при изменении данных на сервере. Обосновать каждое решение и назвать, что станет дороже при росте проекта.

## Упражнения

- **Refactoring exercise:** перевод экрана с контекста на стор (или наоборот) с обоснованием.
- **Performance exercise:** найти селектор, вызывающий лишние рендеры, и доказать это профайлером (возврат к 05).
- **Senior case study:** почему нормализация не окупилась на маленьком экране.
