# 1.1 Variables и scope — theory

> 🟢 REFRESH. Задача урока — не объяснить, что такое переменная, а зафиксировать границы, на которых интуиция ошибается.

## Refresh

### Три объявления и две области видимости

**Scope (область видимости)** — участок кода, внутри которого имя переменной что-то означает. В JavaScript их два вида:

| Объявление | Scope | Повторное объявление | Переприсваивание |
|---|---|---|---|
| `var` | функциональный | можно | можно |
| `let` | блочный | нельзя | можно |
| `const` | блочный | нельзя | нельзя |

**Блок** — это любые фигурные скобки: тело `if`, тело цикла, просто `{ }`. `var` их не замечает — объявление всплывает до начала функции. `let` и `const` видны только внутри своего блока.

```js
function f() {
  if (true) {
    var a = 1;
    let b = 2;
  }
  console.log(a); // 1 — var не ограничен блоком
  console.log(b); // ReferenceError: b is not defined
}
```

### Hoisting и temporal dead zone

**Hoisting (поднятие)** — обработка объявлений до выполнения кода. Поднимаются все три объявления, но ведут себя по-разному:

- `var` поднимается **и инициализируется** значением `undefined`. Обращение до строки объявления даёт `undefined`, а не ошибку;
- `let` и `const` поднимаются, **но не инициализируются**. Промежуток от начала блока до строки объявления называется **temporal dead zone (TDZ)**; обращение в нём бросает `ReferenceError`.

```js
console.log(x); // undefined — var уже существует, но пустой
var x = 1;

console.log(y); // ReferenceError: Cannot access 'y' before initialization
let y = 1;
```

Разница практическая, а не формальная: `undefined` от `var` тихо протекает дальше по коду и ломается позже и не там. TDZ падает сразу в точке ошибки.

> **Важно отличать два разных `ReferenceError`.** «`y` is not defined» означает, что имени нет вообще. «Cannot access `y` before initialization» означает, что имя есть, объявление ниже, и вы в TDZ. Второе сообщение — подсказка о порядке, а не об опечатке.

### `const` запрещает переприсваивание, а не изменение

`const` фиксирует **связь имени со значением**, а не содержимое значения. Для объекта это означает: саму переменную переназначить нельзя, поля менять можно.

```js
const config = { retries: 3 };
config.retries = 5;        // ок — меняем содержимое
config = { retries: 5 };   // TypeError: Assignment to constant variable
```

Это не недоработка языка, а точное описание того, что происходит: в переменной лежит ссылка на объект, и `const` защищает ссылку. Иммутабельность содержимого — отдельная задача и отдельная тема (1.13).

### Shadowing

**Shadowing (затенение)** — объявление переменной с тем же именем во вложенном scope. Внешняя переменная не меняется и не исчезает, она становится недоступна по имени.

```js
const user = { id: 1 };
function render(items) {
  const user = items[0].user; // затеняет внешний user
  // внешний user отсюда недостижим по имени
}
```

Затенение само по себе законно и часто полезно. Опасно оно тогда, когда затеняется неочевидно: параметр функции с именем модульной константы, или `data` внутри `data`. Линтер (`no-shadow`) ловит это раньше ревью.

### Почему `const` по умолчанию

Не из соображений «так чище». `const` сообщает читателю факт, который иначе приходится проверять: **это имя до конца блока означает одно и то же**. При чтении чужого экрана на 200 строк `let` — сигнал «значение меняется, ищи где», `const` — сигнал «можно не искать». `let` ставится там, где переприсваивание действительно есть, и тогда оно заметно.

## RN relevance

### `var` в цикле с асинхронным колбэком

Классический баг в старом коде проекта:

```js
for (var i = 0; i < listeners.length; i++) {
  setTimeout(() => console.log(i), 100); // 3, 3, 3 при трёх итерациях
}
```

`var i` — одна переменная на всю функцию. К моменту, когда колбэки выполнятся, цикл давно закончился и `i` равна своему последнему значению. С `let i` на каждой итерации создаётся **новое** связывание, и каждый колбэк видит своё значение: `0, 1, 2`.

В React Native это выстреливает именно на асинхронном: подписки в цикле, таймеры, последовательные вызовы нативного модуля в цикле. Код, который «работал в тесте с одним элементом», ведёт себя неверно на трёх.

> Почему именно `let` чинит это, разбирается в 1.14: каждая итерация получает собственное замыкание. Здесь достаточно знать, что `var` этого не делает.

### `const ref = useRef()` и `ref.current`

Вопрос, который задают на каждом втором собеседовании: если `ref` объявлен через `const`, почему `ref.current = node` допустимо?

Потому что `const` держит ссылку на объект, который вернул `useRef`, а `current` — поле этого объекта. Переменная не переназначается, меняется содержимое. Ровно та же логика, что у `const config` выше. Это не особенность React, а поведение `const` в чистом JavaScript — и именно поэтому React может построить на нём API.

### Модульный scope живёт всё время работы приложения

Переменная, объявленная на верхнем уровне модуля, существует столько, сколько живёт приложение: модуль выполняется один раз (1.10). В RN это значит, что `let cache = {}` на верхнем уровне файла — не «кэш экрана», а глобальное состояние, которое не очистится при уходе с экрана и переживёт размонтирование компонента. Подробнее о цене этого — в 1.22.

## Типичные заблуждения

**«`const` делает объект неизменяемым.»** Возникает из переноса смысла слова «константа» из других языков, где `const` часто означает неизменяемость всего значения. В JavaScript `const` — это свойство **связывания имени**, и ничего не знает о содержимом. Проверка: `const a = []; a.push(1)` работает.

**«Hoisting означает, что `let` можно использовать до объявления.»** Возникает из упрощённой формулировки «объявления поднимаются наверх». Поднимаются все, но `let` и `const` поднимаются без значения, и до строки объявления находятся в TDZ. Поднятие ≠ доступность.

**«Область видимости определяется функцией.»** Верно для `var` и неверно для `let` и `const` с 2015 года. Заблуждение держится потому, что код с `var` ведёт себя именно так, и опыт чтения старых проектов его подкрепляет.

**«`let` и `var` отличаются только стилистически.»** Отличие наблюдаемое: поведение в цикле с асинхронным колбэком, доступность до объявления, повторное объявление в том же scope. Это три разных наблюдаемых исхода, а не вопрос вкуса.
