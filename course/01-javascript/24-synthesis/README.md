Увидеть все механизмы блока сразу — в одном RN-компоненте — и перейти к блокам 03 и 05 с готовой моделью, а не с набором отдельных фактов.

## Что внутри

Один RN-компонент примерно на 80 строк, в котором одновременно присутствуют семь независимых проблем: инлайн-объект в `style` · цепочка `filter().map()` в теле · подписка на emitter без cleanup · два последовательных `await` · мутация массива из состояния · `?.`, прячущий ошибку контракта · тяжёлая синхронная агрегация.

Для каждого фрагмента разбирается одно и то же: **какой механизм языка здесь работает** (ссылка, замыкание, очередь, достижимость) · **что именно произойдёт в рантайме** · **кто это заметит** (React, сборщик мусора, пользователь) · **в каком блоке курса этот сюжет будет доведён до решения**.

## Главное свойство урока

**Урок сознательно не даёт решений.** Он строит карту.

Это не экономия и не задел на будущее: решение каждой из семи проблем требует знаний, которых на выходе из блока 01 ещё нет. Мемоизация без понимания фаз рендера превращается в расстановку обёрток по интуиции; отмена асинхронной операции без модели гонок — в флаг, который не закрывает реальный случай. Поэтому здесь фиксируется диагноз, а лечение приходит там, где для него есть основания: 03 (мемоизация, зависимости), 05 (замеры, списки, утечки), 06 (иммутабельность в редьюсерах), 07 (отмена и гонки).

Навык, который урок тренирует, — **отличать механизм от симптома**. Это же требование и у checkpoint блока.
