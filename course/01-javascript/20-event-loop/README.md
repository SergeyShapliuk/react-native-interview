## Что внутри

Стек вызовов, очередь задач (task queue), цикл обработки · что именно означает «однопоточность» для JS · блокировка цикла синхронной работой · таймеры и почему `setTimeout(fn, 0)` не означает «сразу» · JS thread в React Native как отдельный поток со своим циклом · взаимодействие с UI-потоком · `InteractionManager`.

## Ключевая формулировка урока

**Поток выполняет одну задачу (task) целиком, до конца, и только потом берёт следующую. «Заблокирован» означает ровно одно: текущая задача ещё не завершилась, поэтому ни одна другая не началась.**

## Границы урока

> **Не вводить модель «в RN ровно три потока».** Это упрощение, которое курс сознательно отвергает: число и роли потоков зависят от архитектуры, версии и используемых библиотек. Здесь достаточно одного различения: **JS thread — не тот поток, на котором система рисует интерфейс.** Уточнение модели исполнения и привязка к инструментам измерения — **5.1**.
>
> **Не дублировать:** точный порядок между обработчиками промисов и таймерами — [1.21](../21-microtasks-and-macrotasks/); бюджет кадра и расчёт в миллисекундах на кадр — 5.2; методика профилирования и инструменты — 5.10; worklet на UI thread — 5.7. Состояния промиса и механика `await` — [1.18](../18-promises/) и [1.19](../19-async-await/).
